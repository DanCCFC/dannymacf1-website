# DannyMacF1 Creator Website

A responsive, static creator website built with plain HTML, CSS and JavaScript. It is designed for GitHub Pages.

## Included
- Creator homepage with TikTok and community calls to action
- Championship leaderboard with sample data
- Subscription tier promotional cards
- Affiliate partner placeholders and disclosure
- Future merch-store section
- Mobile navigation
- Local demo leaderboard editor at `admin.html`

## Before publishing
1. Replace the TikTok URL if your exact handle URL differs.
2. Replace Discord links with your invite URL.
3. Replace partner placeholders with real affiliate URLs and partner names. Keep the affiliate disclosure visible.
4. Edit the tier names and benefits to match your real subscription options. Add prices only after confirming them.
5. The initial leaderboard contains the champions and win totals supplied by DannyMacF1. Update results through the admin prototype as needed.

## Important: leaderboard admin limitation
The included `admin.html` is a **local prototype**, not a secure multi-user admin system. It uses browser `localStorage`, so edits only appear in the same browser and device. Visitors will not see those edits, and there is no authentication. Do not treat this as a live public leaderboard.

For the live version, connect a hosted database and secure admin authentication (for example, Supabase Auth + database with row-level security). The public site should read standings from the database, while only authenticated admins can update results.

## Publish with GitHub Pages
1. Create a new repository on GitHub, for example `dannymacf1-site`.
2. Upload `index.html`, `styles.css`, `app.js`, `admin.html` and this README to the repository root.
3. Open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**.
5. Choose branch `main` and folder `/ (root)`, then save.
6. Wait for GitHub Pages to publish and open the URL shown in the Pages settings.

No build step is required. The site uses Google Fonts; if those are blocked, it falls back to system fonts.

## Free automatic TikTok LIVE banner

The top red banner is hidden by default. The page polls `status.json` every 60 seconds and shows the banner only when `live` is `true`.

A GitHub Actions workflow (`.github/workflows/check-tiktok-live.yml`) checks `@DannyMacF1` approximately every five minutes using the unofficial open-source `TikTokLive` Python library, then commits `status.json` only when the live/offline state changes.

### Enable it on GitHub
1. Upload all files and folders, including the hidden `.github/workflows` folder and `scripts/check_live.py`, to your repository.
2. In the repository, open **Settings → Actions → General** and ensure workflows have permission to read and write repository contents. The workflow declares `contents: write`; repository policy must allow it.
3. Open **Actions**, select **Check TikTok LIVE status**, and choose **Run workflow** once to test it.
4. In **Settings → Pages**, keep publishing from the `main` branch and root folder.

### Free-tier limitations
- GitHub scheduled workflows can be delayed; the banner is not instant and may lag by several minutes.
- TikTokLive is unofficial and may stop working if TikTok changes its systems.
- If the check fails, the banner stays hidden rather than showing a false live alert.
- GitHub Pages is static hosting; the workflow is the separate checker.

## TTDM United FC 27 Pro Clubs integration

The homepage includes a TTDM United Pro Clubs panel for team record, squad stats and recent league results. The data snapshot is generated by `scripts/update_proclubs.py` and published as `proclubs.json`, so GitHub Pages visitors do not call EA directly.

### Enable the data sync
1. Upload all updated files and hidden folders, including `.github/workflows/update-proclubs.yml`, `scripts/update_proclubs.py` and `proclubs.json`.
2. In GitHub, open **Settings → Actions → General** and allow workflows to read and write repository contents (the workflow declares `contents: write`).
3. Open **Actions → Update TTDM United Pro Clubs data → Run workflow** to test the first sync.
4. The workflow is scheduled every three hours. GitHub's free scheduled jobs can run late.

The sync searches for an exact club name match (`TTDM United`) on `common-gen5` (FC 27 current-gen cross-play). It deliberately does not choose a similarly named club automatically. If EA cannot find an exact match, check the team name and platform in `scripts/update_proclubs.py` / workflow configuration. If multiple exact matches exist, the workflow fails rather than risk publishing another team's stats.

The EA endpoints are undocumented and unofficial; EA may block requests or change the response format. This feature is not affiliated with or endorsed by EA. Data may be delayed and will remain at the last published snapshot if a sync fails.


## TikTok follower count

The homepage now has a large follower-count panel linked to `@DannyMacF1`. The GitHub Actions workflow `.github/workflows/update-followers.yml` attempts to read the public TikTok profile every six hours and update `followers.json`.

To enable it, push all files (including the hidden `.github/workflows` folder) to GitHub and allow Actions to have read/write repository permissions under **Settings → Actions → General**. Run **Actions → Update TikTok follower count → Run workflow** once to test it.

**Limitations:** TikTok does not provide a simple, unrestricted public follower-count API for every account. This free method reads the public profile page and may fail if TikTok blocks automated requests or changes its page structure. If it fails, the site keeps the last saved count rather than inventing a number; the workflow run will show the error. The count refreshes approximately every six hours, not in real time.

## Making your own tweaks

The main website files are deliberately kept separate so you can customise them without hunting through everything:

- **`index.html`** — page content and wording, section headings, links, membership details and leaderboard/Pro Clubs structure.
- **`styles.css`** — colours, fonts, spacing, sizes, layout and mobile/laptop responsive rules. The file is formatted with comments. The later `Version 24`–`Version 28` blocks are intentional overrides for the hero layout; edit the latest matching rule first when adjusting the hero.
- **`app.js`** — interactive behaviour: leaderboard rendering, mobile navigation, LIVE banner, Pro Clubs data and follower count. Comments mark each feature.
- **`admin.html`** — a simple local-only leaderboard editor. It saves to that browser's local storage and does not publish changes to other visitors.
- **`assets/`** — the supplied logos and hero image. Replace these only if you want to change the artwork.

### Quick customisation tips

- To change a headline or paragraph, edit the matching text in `index.html`.
- To change the main blue, look near the top of `styles.css` for the `--red` and `--lime` theme variables (both are blue in the current palette). The names are retained for compatibility with older styles.
- To adjust the hero on a laptop, search near the bottom of `styles.css` for `Version 28`. The desktop rule controls `.hero-copy` positioning; `.hero-art` controls the image height. The `#championship` spacing is kept separate so you can adjust one without moving the other.
- To change the built-in leaderboard, edit `DEFAULT_DRIVERS` near the top of `app.js`. Browser-saved leaderboard data can take precedence over these defaults.
- To change external destinations, search `index.html` for the relevant link and replace its `href` value.

**Tip:** make a copy before editing. After changing CSS or JavaScript, refresh the page; if the browser seems to show an old version, do a hard refresh (Ctrl+F5).
